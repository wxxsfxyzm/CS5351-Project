### 1.3 Constrain what the model may say
- **Operator (U4):** "Design a simple prompt that asks the model to evaluate
  two aspects … the likelihood that the APK can be successfully installed on
  the current device, and the potential security risks."
- **Operator (U5):** "Require the model to return JSON in a fixed format … If
  the format is incorrect, fields are missing, or the content is invalid,

- **Agent:** two axes and no verdict. `AssessmentResult` is
  `Valid | Invalid | Missing` with "no third 'assume safe' state and no

- **Type:** redirect (two instructions).
- **Why (stated):** a malformed reply must never default to "safe".
- **Outcome:** strict fixed-format parsing (REQ-IX-INV-004).

### 1.4 Keep the advisor out of the install decision
- **Operator (U6):** "If the AI fails, you only need to report a failure

  routing, no install capability." It added a classified `FailureCode` that
  maps to the runtime policy catalogue.
- **Type:** correct.
- **Why (stated):** installation is decided by deterministic policy, not by
  the advisor.

### 1.5 Fixed test scenarios
